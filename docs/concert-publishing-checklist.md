# Concert publishing and discovery checklist

Use this checklist for every concert before publishing. It supports accessibility, editorial consistency, search visibility, social sharing, and citation by AI-assisted search tools.

## Required event information

- Use a distinct, descriptive concert title rather than a generic title such as “Concert.”
- Confirm the date, start time, time zone, venue name, and complete street address.
- Add the end time only when it is confirmed.
- State admission, parking, accessibility, and accommodation-contact information.
- Include the performers, occasion, repertoire highlights, guest artists, or other details that distinguish the event.
- Provide a working map link and calendar download.
- Update cancellations, postponements, and rescheduled dates immediately.

## Page content

- Write a unique summary and at least one useful paragraph about the specific performance.
- Use one descriptive H1 and logical H2/H3 section headings.
- Link performer, venue, partner, and RSVP names to their authoritative pages.
- Check names, ranks, titles, capitalization, punctuation, and AP-style dates.
- Avoid repeating keywords solely for search engines.

## Images and social sharing

- Supply a representative event image rather than a generic logo whenever possible.
- Prepare high-resolution 16:9, 4:3, and 1:1 versions for metadata and structured data.
- Use short, descriptive filenames.
- Add concise alt text that identifies the subject and its relationship to the event.
- Use empty alt text only when an image is genuinely decorative and adjacent text provides the same information.
- Preview Facebook, LinkedIn, and messaging-app cards before announcing the event.

## Technical validation

- Confirm the canonical URL, title, description, Open Graph image, and Twitter card.
- Validate Event and Breadcrumb structured data with Google’s Rich Results Test.
- Confirm the structured data matches information visible on the page.
- Confirm the URL appears once in `sitemap.xml` with an accurate modification date.
- Test keyboard navigation, focus states, color contrast, mobile layout, and reduced-motion behavior.
- Run the project tests, linting, TypeScript checks, and production build.
- After deployment, inspect the URL in Google Search Console and request indexing for time-sensitive announcements.

## Authority and distribution

- Request direct links from relevant Syracuse University offices, venues, performers, partner organizations, schools, and local event calendars.
- For major events, provide partners with the canonical event URL, approved summary, artwork, press release, and suggested social copy.
- Ask partners to link to the event page rather than copying only the event details into an unlinked post.
- Maintain accurate links from Syracuse University News, OVMA, Hendricks Chapel, Fort Drum or Army pages, and participating music programs when applicable.

## Search and AI monitoring

- Monitor indexing, queries, click-through rate, rich-result errors, and Core Web Vitals in Google Search Console.
- Register and verify the site in Bing Webmaster Tools.
- Submit the sitemap at `https://subrass.syr.edu/sitemap.xml` to both services.
- Review Bing’s AI Performance report for cited pages and grounding queries when it is available for the account.
- Record which event and biography pages earn citations or institutional links, then use those patterns to improve future pages.

Account verification tokens and partner backlinks must be completed by an authorized site owner or participating organization; they cannot be created through the website code alone.
